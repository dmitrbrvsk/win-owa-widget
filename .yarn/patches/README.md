# Исправления зависимостей инструментов разработки

Русский · [English](README.en.md)

Yarn закрепляет локальные патчи и их checksum в lockfile; `yarn install --immutable` применяет их автоматически. Эти зависимости используются инструментами разработки и сборки и не входят в приложение. Стандартный аудит исключает только два advisory, исправленных локальными патчами: npm ID `1240992` и `1241202`. Реестр определяет проблему по версии пакета и не учитывает содержимое патча. Остальные high/critical проблемы продолжают блокировать CI.

## braces 3.0.3

`arui-presets-lint` использует `micromatch`, который зависит от `braces`. Для [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) на 16 октября 2026 года нет опубликованной исправленной версии.

Патч ограничивает глубину стека парсера, рекурсивных обходов compile/expand/stringify и цепочек parent в expand: 128 уровней. Чрезмерная вложенность завершается контролируемой ошибкой вместо переполнения стека или зависания. Лимит распространяется и на скобки, и на круглые скобки; поведение `escapeInvalid` сохранено.

`test/toolingSecurity.test.ts` проверяет все публичные методы, переданный AST и цикл parent в дочернем процессе с таймаутом, а также обычные шаблоны. Без патча тесты не проходят. Исключение аудита: только npm ID `1240992`.

После выпуска исправленного upstream-пакета обновите зависимость, удалите патч, resolution и исключение `1240992`. Регрессионную проверку можно сохранить для новой версии.

## sprintf-js 1.1.3

Цепочка `electron-builder` → `@electron/get` → `global-agent` → `roarr` использует `sprintf-js`. Для [GHSA-hp3w-g68c-fv3c](https://github.com/advisories/GHSA-hp3w-g68c-fv3c) на 16 октября 2026 года нет опубликованной исправленной версии.

Патч меняет только числовую точность `%e`, `%f` и `%g`: перед передачей встроенным методам Number она ограничивается диапазоном **0–100 для e/f** и **1–100 для g**. Длинная строка цифр, превращающаяся в `Infinity`, дает верхний предел 100; `%.0g` использует точность 1. Таким образом, слишком большая точность не вызывает `RangeError`. Форматы без точности, допустимая точность, знаки, выравнивание, дополнение и нечисловые преобразования сохраняют прежнее поведение. Ширина поля не меняется: этот патч устраняет конкретный advisory о точности, а не разрешает произвольные недоверенные форматные строки.

Одинаковая защита добавлена в Node entry `src/sprintf.js` и поставляемый `dist/sprintf.min.js`. `test/toolingFormattingSecurity.test.ts` проверяет оба entry у всех установленных копий в дочерних процессах с таймаутом: точность 101, миллиард, 400 цифр, ноль и обычные `sprintf`/`vsprintf`. Без патча проверка опасной точности падает с `RangeError`. Исключение аудита: только npm ID `1241202`; обновление `@electron/get` через несовместимую major-версию не требуется.

После появления исправленной upstream-версии обновите совместимую цепочку, удалите патч, resolution и исключение `1241202`; выполните регрессионные тесты и сборку.

## KaTeX 0.18.2

`micromark-extension-math` 3.1.0 пока объявляет зависимость `katex: ^0.16.0`. Узкий resolution `katex@npm:^0.16.0` выбирает **0.18.2**, где исправлен [GHSA-238p-pmpm-9mq7](https://github.com/advisories/GHSA-238p-pmpm-9mq7). Исключения аудита для KaTeX нет.

`test/toolingFormattingSecurity.test.ts` проверяет `renderToString`, явный `trust: true`, игнорирование унаследованного `trust` и загрязненного `Object.prototype`, а также inline/block math через настоящий micromark с `mathHtml`. Проверки опасного наследования изолированы в дочерних процессах. Они воспроизводили проблему до обновления и проходят после него.

Удалите resolution, когда совместимая версия `micromark-extension-math` начнет выбирать исправленный KaTeX самостоятельно. При дальнейших обновлениях сохраняйте проверки интеграции и границы `trust`.
