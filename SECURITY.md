## Как проверить скачанный файл

Установщик пока не подписан сертификатом Windows, поэтому SmartScreen может предупредить о нём. Перед запуском сверьте файл с релизом:

```powershell
Get-FileHash .\OWA-Widget-Setup-<версия>.exe -Algorithm SHA256
```

Результат должен совпасть со строкой в `SHA256SUMS.txt` на странице релиза. Кроме того, каждый `.exe` имеет подтверждение происхождения: оно доказывает, что файл собран из этого репозитория workflow'ом GitHub Actions, а не загружен вручную.

```powershell
gh attestation verify .\OWA-Widget-Setup-<версия>.exe --repo dmitrbrvsk/win-owa-widget
```

Скачивайте только со страницы [Releases](https://github.com/dmitrbrvsk/win-owa-widget/releases) этого репозитория.

## Новые локальные функции

- **Группы участников:** до 30 групп на аккаунт, до 20 адресов в группе; файл `groups.bin` зашифрован через `safeStorage` (на Windows — DPAPI). Без шифрования запись отклоняется. Группы привязаны к серверу и способу входа / логину; адреса не уходят на сторонние сервисы. Проверка занятости выбранных участников идет в Exchange.
- **Приватность:** включается вручную и сохраняется между запусками. Во всех окнах виджета остается только календарь со временем и общей занятостью; карточки, формы, имена, адреса и заметки скрыты. Новые напоминания и подсказка трея используют обезличенные события. Уже показанные уведомления закрываются по возможности. Историю уведомлений Windows, буфер обмена, открытые системные диалоги и сторонние приложения этот режим очистить или скрыть не может — включайте его до демонстрации экрана.
- **Отчет для поддержки:** отдельная сборка полей по разрешенному списку: версия, ОС/архитектура, время, фаза синхронизации, результаты четырех этапов подключения, категория ошибки, HTTP-статус и известный технический код. Нет адреса сервера, логина, пароля, cookies, сертификата, путей, текстов ошибок или встреч. Отчет можно скопировать и просмотреть в настройках; отправка — только вручную.
- **Обновления:** один GET к фиксированному API релизов этого репозитория, только по нажатию. Отдельная сессия, без cookies и учетных данных, без перенаправлений; таймаут 10 секунд, ответ до 128 КБ. Сравниваются только стабильные числовые версии. Открыть можно только проверенную ссылку релиза этого репозитория. Браузер затем открывает GitHub обычным способом; загрузка и установка остаются ручными.
- **Горячие клавиши (с 1.6.0):** приложение регистрирует в Windows только три сочетания из настроек (по умолчанию Ctrl+Alt+J/W/N) и получает только их нажатия; остальной ввод с клавиатуры оно не видит. Сочетание без двух модификаторов или с клавишей Windows не принимается. Не чаще 20 срабатываний в минуту. Ctrl+Alt+J открывает ссылку только одной встречи, которая идет или начнется в ближайшие 10 минут, той же проверкой адресов, что и кнопка «Подключиться»; при нескольких звонках и в режиме приватности открывается виджет. В журнал пишется только исход («join», «choose», «none»), без названий. Временно отпустить сочетания (пока поле записывает новое) может только окно настроек; при его закрытии они возвращаются.
- **Частые участники и места (с 1.6.0):** адреса, имена и места созданных в виджете встреч хранятся в `recent/<хеш владельца>.bin`, отдельно для каждого аккаунта, зашифрованно через `safeStorage`; без шифрования ничего не записывается. Файл читается строго (до 200 человек и 50 мест, забываются через 180 дней без использования), чужой или поврежденный файл не используется и не перезаписывается. Подсказки собираются локально и никуда не отправляются; в режиме приватности окна их не получают. «Забыть частых участников» удаляет файл текущего аккаунта.
- **Свободные окна (с 1.6.0):** считаются в окне из уже загруженных встреч, без запросов к серверу.

## Что делает приложение с вашими данными

- При выключенном MCP календарь и учетные данные передает только серверу Exchange из настроек. Отдельное разрешение MCP описано ниже; учетные данные через него недоступны. Отдельное исключение — ручная кнопка «Проверить обновления»: она запрашивает последний релиз у `api.github.com`. Без нажатия запросов обновлений нет; телеметрии и автоматической установки нет. Страницы интерфейса запрещают любые сетевые соединения (`connect-src 'none'`).
- Для запросов к Exchange — только HTTPS и только тот же сервер. Первый запрос, каждое перенаправление и каждый запрос авторизации должны идти на `https://` и на тот же хост **и порт**, что настроены. Адрес с `http://`, другим хостом или другим портом отклоняется до отправки, поэтому пароль и сессия не уходят на чужой сервер или открытым текстом.
- Пароль шифруется средствами Windows (DPAPI) и хранится в профиле пользователя. Если шифрование недоступно, пароль не сохраняется вообще. Кеш встреч шифруется так же.
- **Пароль привязан к серверу.** Внутри зашифрованного файла вместе с паролем записан адрес сервера, для которого он введён. Для любого другого адреса приложение пароль не отдаёт, даже если файл настроек изменили. Пароль, сохранённый версией до 0.2.0 (в ней он лежал без записи о сервере), не используется и стирается при первом запуске: его нужно ввести заново. Привязать его к адресу, который сейчас в файле настроек, значило бы отдать пароль серверу, который человек не подтверждал.
- **Смена сервера подтверждается в системном окне.** Указать другой сервер значит отправить на него логин, пароль и (при пустом логине) данные учётной записи Windows. Поэтому при сохранении настроек и при проверке подключения с новым адресом приложение показывает окно Windows, которое страница интерфейса не может нажать. Старый пароль на новый сервер не переносится: его вводят заново. За раз открыто не больше одного такого окна.
- Встроенный вход Windows (Kerberos / NTLM) разрешён только для вашего сервера (сверяются хост и порт).
- Логин и пароль отправляются только в собственную форму входа OWA (`…/auth.owa` на указанном сервере, по https, с того же адреса) и только если сервер действительно показал её. Страница 404, портал или форма прокси-сервера пароль не получат: приложение остановится и объяснит, что увидело. Адрес почты в поле сервера отклоняется сразу.
- Неверный пароль — одна попытка, после неё приложение не входит снова до подтвержденного повторного входа в настройках: ни по расписанию, ни по кнопке «Обновить», ни по запросу от окна интерфейса. Доменная учётная запись блокируется после нескольких неудачных входов, и эти попытки нельзя дать потратить ни человеку в спешке, ни зациклившейся странице.
- Сертификат проверяется по хранилищу Windows. Довериться внутреннему сертификату можно только в системном окне с отпечатком, и приложение запоминает именно этот отпечаток для этого хоста. Страница не может подтвердить доверие сама.
- Подсказки людей при создании встречи, занятость участников, запрос встреч за период для статистики и сами встречи уходят **только** на настроенный сервер Exchange, по тому же защищённому каналу, что и остальные запросы (https, тот же хост и порт, проверка сертификата). Поиск по встречам и контекстное меню «Копировать» работают локально: запрос поиска никуда не отправляется и в журнал не пишется.
- **Личные заметки к встречам** хранятся только в зашифрованном файле профиля (тем же способом, что и кеш). Они не отправляются ни на сервер Exchange, ни куда-либо еще: ни в запросах, ни в журнале. Если шифрование недоступно, заметка не сохраняется и человеку об этом сообщается. Лимиты: до 5000 символов в заметке, не больше 500 заметок, не больше 60 записей в минуту; заметка принимается только к встрече из синхронизированного списка; заметки к встречам старше 92 дней стираются сами. «Удалить заметки аккаунта» в настройках требует подтверждения в системном окне.
- «Сбросить кэш» (Настройки → Диагностика) стирает сохранённый список встреч и сеанс на сервере. Пароль, сертификат и настройки остаются.
- Права администратора не нужны ни для установки, ни для работы. При удалении через установщик стираются настройки, зашифрованный пароль, кэш и журнал.

## Локальный MCP (с 1.5.0)

По умолчанию MCP выключен. Включение чтения и расширение доступа к названиям требуют системного подтверждения; выключение действует сразу. Доступны время и статус только загруженных встреч, а названия — по отдельному разрешению. Режим приватности скрывает названия и запрещает поиск по ним. Участники, описания, места, ссылки, заметки, Exchange ID, учетные данные и операции записи недоступны. Смена аккаунта отзывает доступ.

Стандартный транспорт MCP — stdio через отдельный CLI на Node 24.22+. Внутренний локальный мост проверяет Host/Origin и ограничивает размеры и время запросов. Секрет подключения не попадает в интерфейс и копируемую конфигурацию. Запросы и привязанные к запросу ответы защищены AES-256-GCM со случайными nonce. В Windows защита зависит от унаследованных прав доступа профиля; процесс того же пользователя или администратора может прочитать ключ. От компрометации учетной записи это не защищает.

**При включении MCP данные календаря могут покинуть виджет через подключенный клиент.** Клиент может передать их ИИ-провайдеру или записать в журнал. Уже переданные данные отозвать нельзя. Перед включением проверьте правила компании и настройки клиента. Подключение, ограничения и безопасная диагностика: [руководство MCP](docs/MCP.md).

## Исправления аудита в версии 1.5.0

- Ключ владельца различает Windows SSO и ручной логин `windows`. Миграция сохраняет зашифрованные оригиналы, требует системного решения для неоднозначных записей и не назначает один источник двум аккаунтам. Прерванный перенос возобновляется только для выбранного владельца. [Перенос данных](docs/GUIDE.md#перенос-данных-старых-аккаунтов).

- Подтверждение сертификата привязано к показанным хосту, отпечатку и версии аккаунта; изменения во время системного диалога отменяют согласие.
- Режим реального подключения совпадает с владельцем локальных данных. Если пароль ручного входа временно недоступен, подключение останавливается без перехода на Windows SSO.
- Заметки имеют зашифрованного владельца аккаунта. Старый `notes.bin` без владельца сохраняется без чтения и автоматического импорта; см. [Заметки](docs/GUIDE.md#заметки). Непрочитанные заметки и группы нельзя затереть последующим сохранением.
- JSON сервера проверяется до создания объектов: до 48 уровней, 1024 свойств объекта, 6000 элементов массива и 200000 структурных токенов, дополнительно к лимиту байтов HTTP. Обходчики также ограничивают фактически просмотренные узлы и работу с массивами. Чрезмерная структура отклоняется вместо зависания приложения.
- MCP использует отдельный лимит одновременной работы до аутентификации. Лимит 120 операций в минуту расходуют только аутентифицированные корректные конверты. Абсолютный срок соединения — три секунды, включая медленную передачу заголовков и тела.

## Текст от посторонних

Названия, описания и места встреч, ссылки и страницы сервера приходят от людей, которым вы не доверяете безоговорочно. Поэтому:

- Разбор писем и страниц сделан за линейное время и с ограничениями: поиск ссылок, преобразование HTML в текст и разбор формы входа не используют регулярные выражения, которые на специально составленном тексте работают секундами. Размеры текста, число встреч (3000), участников и скрытых полей формы ограничены. Приглашение с «ядовитым» содержимым не может подвесить приложение.
- Названия, организаторы, места и описания очищаются от управляющих символов, от символов, меняющих порядок отображения текста (включая метки направления), и от невидимых символов нулевой ширины, обрезаются по длине и не могут добавить строки в журнал, пункты меню, окна подтверждения или уведомления. Текста, которого не видно, в них не остаётся: иначе им можно было бы «обнулить» то, что человек читает.
- Ссылки открываются только как `http(s)`, без логина в адресе и без скрытых символов. Больше того: открыть можно только ту ссылку, которую приложение само выдало окну — ссылку на звонок встречи и ссылки из места и описания, которые оно же нашло. Любую другую окно открыть не может, поэтому браузер нельзя использовать как канал наружу. Сырой HTML письма в окно интерфейса не передаётся. Содержимое кэша на диске проверяется при загрузке так же строго, как ответ сервера.
- Ссылка открывается только после того, как её показали: у кнопки «Подключиться» для незнакомого сайта рядом написан настоящий хост, а у известных сервисов он виден в подсказке. Приложение не открывает ничего само.

## Уведомления

- Уведомление не несёт данных: нажатая кнопка приходит как номер в списке, который собрало приложение, а действие выполняется из состояния главного процесса. Подделать нажатие снаружи приложения нельзя.
- «Принять» есть только у уведомления о новом приглашении и отправляет только ответ «Принять» на эту встречу, как кнопка в окне. После этого приложение сообщает об успехе или ошибке.
- Уведомлений об изменениях не больше шести в час, а при массовых изменениях приходит одно общее. Сервер не может завалить вас уведомлениями.
- Если уведомление Windows не удалось показать, показывается собственное окно напоминания.

## Создание, изменение и отмена встреч, свободное время

Эти функции отправляют письма от вашего имени, поэтому защищены строже остальных. Всё сказанное ниже про создание встречи в той же мере относится к её изменению и отмене: это тот же путь в главном процессе, те же проверки, те же лимиты и такое же системное окно.

- **Ответ с комментарием и «другое время» — тоже письмо от вашего имени.** Ответ идёт тем же путём, что создание и изменение: одна отправка за раз, проверка в главном процессе, общие лимиты, подтверждение в системном окне с полным текстом ответа (по умолчанию и по Esc «Отмена»). Проверяется, что это чужое, не отменённое приглашение с известным ключом изменения; комментарий очищается и ограничен 1000 символами; предложенное время — корректный интервал не длиннее 12 часов, не в прошлом и не дальше года. Текст уходит только в `NewBodyContent` обычного ответа на приглашение, отдельным письмом или встречным предложением Outlook он не является.
- **Изменение и отмена — тоже рассылка.** Перенос встречи сообщается всем приглашённым, а отмена уходит уведомлением каждому, включая тех, кого только что убрали из списка. Поэтому и то и другое подтверждается в системном окне: в окне изменения показано, что именно меняется (старое и новое время, добавленные и убранные участники), в окне отмены — скольким людям уйдёт уведомление и что вернуть встречу нельзя. Безопасный ответ выбран по умолчанию и срабатывает на Esc.
- **Что меняется, решает главный процесс.** Он сам смотрит, какой встреча была (из синхронизированного списка и с сервера), сравнивает с тем, что прислало окно, и отправляет только отличающиеся поля. Окно не может ни описать изменение, которого не было, ни подсунуть свой «прежний» вид встречи в окно подтверждения.
- **Повторяющаяся встреча ограничена:** не больше 100 повторений и не дальше двух лет; сколько их будет, написано в окне подтверждения, потому что каждое повторение — это запись в чужом календаре.
- **Подтверждение в системном окне.** Если у встречи есть участники, приглашения уходят только после ответа «Отправить» в окне Windows. Текст окна собирает главный процесс из уже проверенной встречи (тема, время, место, начало описания, получатели: первые 15 и «и еще N»), а не принимает от окна интерфейса; по умолчанию и по Esc выбрано «Отмена». Если тема, место или описание не поместились целиком, после обрезанной строки написано, сколько в ней символов всего: прочитанное в окне не может оказаться короче отправленного. Страница нажать это окно не может, поэтому даже скомпрометированное окно интерфейса не способно разослать приглашения. Личная встреча без участников тоже требует подтверждения перед записью: неподтвержденное содержимое не может само разрешать внешние ссылки.
- **Порядок проверок в главном процессе:** одна отправка за раз → проверка всех полей (данные от окна интерфейса не доверенные) → лимиты → подтверждение → повторная проверка лимитов (пока открыто окно, время идёт) → запрос. Лимиты (общие для создания, изменения и отмены): не больше 10 операций и 300 получателей в час и 12 окон подтверждения за 10 минут, не больше 100 адресов в каждом из двух списков (обязательные и необязательные), тема и место до 500 символов, описание до 20 000, встреча не длиннее 7 суток и не дальше двух лет от сегодня.
- **Только обычные адреса.** Адрес получателя принимается, если он состоит из ASCII-символов (латинские буквы, цифры и обычные знаки): адрес с «похожими» символами другого алфавита, пробелами, угловыми скобками или управляющими символами отклоняется до окна подтверждения и до запроса. Запрос не строится из адреса, который не прошёл проверку, даже если вызывающий код её пропустил.
- **Запросы к Exchange собираются без доступа к разметке.** Каждое подставляемое значение проходит через экранирование (`& < > " '`), символы, которых XML не допускает, и парные суррогаты-«сироты» удаляются; поэтому тема вроде `</Subject><Evil/>` остаётся текстом. Время уходит как точный момент в UTC, и смена летнего времени ничего не сдвигает.
- **Ответ сервера читается строго.** «Создана» — и так же «ответ на приглашение отправлен» — засчитываются только при явном `ResponseClass="Success"`, с любым префиксом пространства имён: страница ошибки, пустой ответ, ответ в другой разметке и обрыв посреди ответа успехом не считаются, и человеку не сообщается об успехе, которого не было. Сообщения об ошибках составляет приложение по коду ответа, текст сервера в интерфейс и журнал не попадает. Разбор XML однопроходный, без DOM и без раскрытия сущностей (определение типа документа пропускается), с ограничениями на размер ответа (не больше 8 МБ), число токенов и длину имён, так что «ядовитый» ответ не может ни подвесить окно, ни занять память.
- **Изменить и отменить может только организатор** — приложение проверяет это само, а не доверяет окну; уже отменённую встречу отменить нельзя.
- **Повтора отправки нет.** Если связь оборвалась, пока ответ был в пути, приложение не отправляет запрос повторно (второе приглашение ушло бы всем) и просит сначала проверить календарь. Единственное исключение — создание встречи, в которой нет ни одного участника (писем не уходило): если сервер сообщил, что не знает часовой пояс компьютера, такая встреча сохраняется повторным запросом без пояса. У изменения и отмены повторов нет вовсе. Когда участники есть, повтора нет и в этом случае: «не принял часовой пояс» — это слово сервера, а не доказательство, что приглашения не ушли.
- **Подсказки из адресной книги:** не больше 60 запросов в минуту, запрос ограничен по длине и очищен, из ответа берутся не больше 8 человек и только с корректным SMTP-адресом (старые адреса X.500 в приглашение не подставить), имена очищаются от управляющих символов и скрытых символов направления текста.
- **Занятость:** не больше 20 адресов и 14 дней за запрос, окно не дальше трёх лет от сегодня, интервал запроса приложение задаёт само; одновременно выполняется один запрос, и не больше 30 запросов за 10 минут. Ответ читается линейно, с ограничением на число людей, промежутков и длину строки занятости, неизвестные символы считаются «нет данных», а названия чужих встреч очищаются и показываются только там, где Exchange их отдал (закрытые не показываются).
- **Статистика встреч:** окно запрашивает встречи за период одним `GetCalendarView` — тем же запросом, что и обычная синхронизация, без других полей. Период проверяется до запроса (не длиннее 60 дней, не дальше двух лет от сегодня); одновременно выполняется один запрос, не больше 20 за 10 минут. Ответ не попадает в кэш и не подменяет синхронизированный список, все вычисления идут на вашей машине, и наружу из них ничего не уходит.
- **Остальные запросы тоже ограничены.** Открытие карточки встречи и ответ на приглашение — не больше трёх одновременно и 120 за десять минут; подсказки людей — 60 в минуту; занятость — один запрос за раз и 30 за десять минут; встречи за период для статистики — один запрос за раз и 20 за десять минут; меню «Копировать» — 20 открытий в минуту. Страница в цикле не превращается в поток запросов от вашего имени.
- **Журнал** содержит только исходы и счётчики («создана, приглашено 3», «запрошено 4 ящика, ответили 4»), без адресов, тем и текстов.
- Переменные `OWA_E2E_AUTOCONFIRM` (ответ автотеста на системные окна: отправка, ответ на приглашение, удаление заметок) и `OWA_POPUP_IDLE_MS` (срок, через который освобождается скрытое окно виджета) работают только в сборке для разработки; в установленной и portable-сборке они игнорируются.

## Журнал диагностики

В профиле пользователя (`%APPDATA%\OWA Widget\logs\owa-widget.log`, до 1 МБ) ведётся журнал: адреса запросов без параметров, коды ответов, причины ошибок сертификата, события окон, количество изменений в календаре и показанных уведомлений. В нём нет паролей, cookie, canary, заголовков, тел ответов, названий и содержимого встреч. Одна запись занимает одну строку: текст из ответа сервера или сертификата не может добавить в журнал строки от своего имени. Журнал никуда не отправляется; открыть папку с ним можно из настроек.

## Как защищено приложение

- Иконку и подсказку в трее рисует сам главный процесс по календарю, который у него уже есть. Окно у трея не может ни задать иконку, ни написать подсказку: такого канала у него нет. Само окно создаётся по щелчку и закрывается через три минуты после того, как его скрыли; оно работает в той же песочнице, что и остальные.
- Окна работают в песочнице (`sandbox`, `contextIsolation`, без `nodeIntegration`), не могут открывать новые окна, переходить на чужие адреса (в том числе из вложенных фреймов) и запрашивать разрешения.
- Главный процесс отвечает только собственной странице интерфейса и проверяет каждый аргумент: настройки пересобираются по полям, числа ограничиваются, действия и адреса проверяются. Мигание иконки главный процесс ограничивает сам: не дольше 150 секунд за раз и только пока идёт обратный отсчёт. Меню «Копировать» по правой кнопке мыши строится в главном процессе: страница присылает только номер встречи, а текст для буфера обмена берётся из данных, которые уже есть у главного процесса.
- В установленной сборке отключены `ELECTRON_RUN_AS_NODE`, `NODE_OPTIONS`, `--inspect`, DevTools, демо-режим и dev-сервер; приложение загружается только из `app.asar`, а целостность `app.asar` проверяется по хешу внутри `.exe`: подменённый архив не запустится.
- Сборка идет в GitHub Actions: зависимости и действия закреплены по хешам, установка пакетов идет без их скриптов (`yarn install --immutable` с `enableScripts: false`), кэш зависимостей в сборке не используется, шаги сборки не получают токен с правом записи, релиз публикует отдельное задание. После сборки CI запускает получившийся `.exe` и проверяет, что окна открылись, а журнал не содержит ошибок.

## Известные ограничения

- Установщик не подписан (нужен сертификат Authenticode). До подписи пользуйтесь проверкой выше: подтверждение происхождения выдаётся и на `SHA256SUMS.txt`, поэтому подменить установщик вместе со списком сумм незаметно не выйдет.
- Приложение ставится в профиль пользователя, поэтому его файлы доступны на запись всему, что запущено от вашего имени. Проверка целостности `app.asar` и отключённые «фьюзы» защищают от подмены архива с кодом, но не от подмены самого `.exe`: и хеш, и фьюзы записаны внутри него.
- Защита от программ, запущенных **от вашей учётной записи**, ограничена. Пароль под DPAPI защищён от других пользователей компьютера, но такая программа может вызвать DPAPI от вашего имени. Она же может изменить файл настроек (адрес сервера, закреплённый сертификат), минуя системное окно подтверждения: сохранённый пароль при этом останется привязан к прежнему серверу, но вход под учётной записью Windows (при пустом логине) пойдёт на любой сервер, записанный в файле. Так устроена модель защиты пользовательских данных Windows.
- Ссылка в приглашении может вести на сайт злоумышленника, если приглашение прислал он. Как и в Outlook, смотрите, от кого письмо и куда ведёт ссылка (хост показывается в подсказке, а у незнакомых сайтов и на самой кнопке).
- Среди инструментов разработки (не входят в готовое приложение) есть зависимости с известными предупреждениями среднего уровня в аудите Yarn: они не попадают в установщик. Сборка останавливается на предупреждениях уровня high и critical в любом месте дерева зависимостей, включая сам Electron.
- Программа, запущенная **от вашей учётной записи**, может обратиться к серверу тем же путём, что и приложение, в том числе создать встречу: подтверждение защищает от случайной или подставленной отправки из окон самого приложения, но не от кода, уже работающего под вашим пользователем.
- Уведомления Windows с кнопками, системное окно подтверждения отправки, мигание иконки в настоящем трее Windows и сам Windows-вход против настоящего Exchange не проверялись, как и **создание встреч, подсказки людей и поиск свободного времени против настоящего Exchange**: сначала прогоните приложение на своём сервере, а первую встречу создайте без участников.

## Сообщить об уязвимости

Если доступна форма [Security → Report a vulnerability](https://github.com/dmitrbrvsk/win-owa-widget/security/advisories/new), используйте ее для приватного сообщения владельцу репозитория. Если форма недоступна, создайте публичный issue только с просьбой указать приватный канал связи, без подробностей уязвимости, данных для входа или содержимого календаря. Не публикуйте технические подробности в открытых issues, пока исправление не выпущено.


### Изоляция сессий календаря

Каждая смена параметров подключения делает прежние запросы недействительными и отменяет сетевую работу старого клиента. Результаты и ошибки принимаются только от актуальной сессии. Кеш календаря содержит зашифрованный идентификатор аккаунта; старый формат без владельца пересоздается после подключения к Exchange. Смена аккаунта закрывает окна с карточками, поиском, напоминаниями и черновиками прежней сессии.

Блокировка повторной авторизации после неверного пароля действует для всех календарных операций. Ошибки чтения необязательных локальных файлов не прерывают запуск. Непрочитанный файл заметок сохраняется, а запись в него блокируется до восстановления доступа и повторного запуска.


При полном сбросе подключения очищаются не только cookies, но и отдельный кеш HTTP-авторизации Chromium; открытые соединения закрываются до начала новой сессии. Журнал блокировок навигации и новых окон сохраняет только origin, без пути, параметров и фрагмента ссылки встречи. Сам диагностический журнал все равно может содержать внутренние адреса серверов и сведения о сертификатах: перед публичной отправкой его нужно проверить. Для публичного обращения используйте безопасный отчет из настроек.

### Результат углубленного аудита (1.4.3)

Личные встречи без участников также требуют системного подтверждения при создании, изменении и отмене. Неподтвержденная запись не может добавить свою ссылку в список адресов, разрешенных для открытия браузером.

После ошибки авторизации очистка кеша, пересоздание клиента и операции с сертификатом не снимают блокировку входа. Повторная проверка подключения или сохранение исправленных учетных данных требуют системного подтверждения; запросить его можно не чаще одного раза в 30 секунд. Отмена и ошибка сохранения не разрешают новый вход. Успешная проверка с сохраненными учетными данными возобновляет синхронизацию; проверка с еще не сохраненным паролем не разрешает автоматические попытки со старым паролем. Ограничение действует в текущем процессе и не заменяет политику домена.

### Изолированный источник интерфейса (1.4.4)

Все окна используют внутреннюю схему `owa-widget://app/index.html`; локальный HTTP-сервер и регистрация ссылок в Windows не создаются. Схема доступна только внутри приложения и обслуживает из каталога renderer единственную HTML-страницу и собранные JS/CSS. Остальные файлы, хосты, методы записи, чужие инициаторы, ссылки за пределы каталога и исходные карты отклоняются. Дополнительные права `file://` отключены fuse `grantFileProtocolExtraPrivileges: false`; IPC от файловых URL больше не принимается. CSP, песочница и изоляция контекста сохраняются, обход CSP и service workers не разрешаются.

Упакованная сборка в CI должна не только запуститься, но и подтвердить загрузку интерфейса со стилями и рабочим preload. Сообщение готовности содержит только постоянный технический маркер, без содержимого календаря.
