# Безопасность

## Как проверить скачанный файл

Установщик пока не подписан сертификатом Windows, поэтому SmartScreen может предупредить о нём. Перед запуском сверьте файл с релизом:

```powershell
Get-FileHash .\OWA-Widget-Setup-<версия>.exe -Algorithm SHA256
```

Результат должен совпасть со строкой в `SHA256SUMS.txt` на странице релиза. Кроме того, каждый `.exe` имеет подтверждение происхождения: оно доказывает, что файл собран из этого репозитория workflow'ом GitHub Actions, а не загружен вручную.

```powershell
gh attestation verify .\OWA-Widget-Setup-<версия>.exe --repo dmitrbrvsk/win-owa-widget
```

Скачивайте только со страницы [Releases](https://github.com/dmitrbrvsk/win-owa-widget/releases) этого репозитория.

## Что делает приложение с вашими данными

- Обращается **только** к серверу Exchange, адрес которого вы указали. Других сетевых запросов нет: ни телеметрии, ни автообновления, ни сторонних сервисов. Страницы интерфейса запрещают любые сетевые соединения (`connect-src 'none'`).
- Только HTTPS. Адрес с `http://` отклоняется, перенаправление на другой хост или на `http://` обрывает запрос, поэтому пароль и сессия не уходят на чужой сервер.
- Пароль шифруется средствами Windows (DPAPI) и хранится в профиле пользователя. Если шифрование недоступно, пароль не сохраняется вообще. Кеш встреч шифруется так же.
- Встроенный вход Windows (Kerberos / NTLM) разрешён только для вашего сервера.
- Логин и пароль отправляются только в собственную форму входа OWA (`…/auth.owa` на указанном сервере) и только если сервер действительно показал её. Страница 404, портал или форма прокси-сервера пароль не получат: приложение остановится и объяснит, что увидело. Адрес почты в поле сервера отклоняется сразу.
- Неверный пароль — одна попытка, после неё автоматическая синхронизация останавливается до изменения настроек, чтобы доменная учётная запись не была заблокирована.
- Сертификат проверяется по хранилищу Windows. Довериться внутреннему сертификату можно только в системном окне с отпечатком, и приложение запоминает именно этот отпечаток для этого хоста. Страница не может подтвердить доверие сама.
- Права администратора не нужны ни для установки, ни для работы.

## Журнал диагностики

В профиле пользователя (`%APPDATA%\OWA Widget\logs\owa-widget.log`, до 1 МБ) ведётся журнал: адреса запросов без параметров, коды ответов, причины ошибок сертификата, события окон. В нём нет паролей, cookie, canary, заголовков, тел ответов, названий и содержимого встреч. Журнал никуда не отправляется; открыть папку с ним можно из настроек.

## Как защищено приложение

- Окна работают в песочнице (`sandbox`, `contextIsolation`, без `nodeIntegration`), не могут открывать новые окна, переходить на чужие адреса и запрашивать разрешения.
- Главный процесс отвечает только собственной странице интерфейса и проверяет каждый аргумент: настройки пересобираются по полям, числа ограничиваются, действия и адреса проверяются.
- Ссылки открываются только как `http(s)` и без логина в адресе. Хоткей Ctrl+Alt+J открывает без просмотра только `https`-ссылки известных сервисов (Teams, Zoom, Webex, Google Meet, KTalk); незнакомую ссылку он показывает в окне. У кнопок «Подключиться» в подсказке виден настоящий хост.
- Текст приглашений приходит от посторонних людей, поэтому разбор ограничен по размеру и времени.
- В установленной сборке отключены `ELECTRON_RUN_AS_NODE`, `NODE_OPTIONS`, `--inspect`, DevTools, демо-режим и dev-сервер.
- Сборка идёт в GitHub Actions: зависимости и действия закреплены по хешам, шаги сборки не получают токен с правом записи, релиз публикует отдельное задание.

## Известные ограничения

- Установщик не подписан (нужен сертификат Authenticode). До подписи пользуйтесь проверкой выше.
- Пароль под DPAPI защищён от других пользователей компьютера, но не от программ, запущенных от вашей учётной записи: так устроено шифрование Windows для пользовательских данных.
- Ссылка в приглашении может вести на сайт злоумышленника, если приглашение прислал он. Как и в Outlook, смотрите, от кого письмо и куда ведёт ссылка (хост показывается в подсказке).
- Приложение не проверялось на реальном Exchange и на Windows: сначала прогоните его на своём сервере.
