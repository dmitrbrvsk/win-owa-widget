# Проверка и форматирование кода

Русский · [English](LINTING.en.md)

Проект использует `arui-presets-lint` (ESLint с проверкой типов, Stylelint и Prettier). Линтеры нужны только при разработке и не включаются в приложение.

```sh
yarn lint          # Проверка JS/TS, CSS и форматирования, без изменения файлов
yarn lint:fix      # Автоисправления и форматирование
yarn format       # Только форматирование
yarn typecheck
yarn test
yarn build
```

После автоисправлений обязательно проверьте diff, типы и тесты: изменение синтаксиса иногда требует ручной корректировки. CI запускает `yarn lint` и запрещает предупреждения.

## Адаптация пресета

- ESLint использует оба существующих TypeScript-проекта: renderer и Electron/тесты. Проверки с информацией о типах включены.
- camelCase модулей и PascalCase компонентов сохраняются; новые имена также проверяются. Зависимости приложения находятся в devDependencies, поскольку esbuild и Vite включают их в сборку.
- Оператор `void` разрешен как отдельная инструкция для явно фоновой работы; проверка необработанных промисов остается включенной. Инкремент разрешен в счетчике цикла.
- Условные подписи интерфейса и парные переводы могут использовать вложенные тернарные выражения. CLI-скрипты могут писать результат в консоль.
- Для существующих больших модулей заданы явные пределы размера и сложности в `eslint.config.mjs`. Это исходные границы для постепенного рефакторинга; новые модули используют ограничения пресета. Миграция оформления не требует одновременно разбивать парсеры протоколов и экраны на новые модули.
- Точечные исключения в исходниках поясняют намеренные битовые операции, последовательные запросы, вредоносные тестовые данные и особенности Electron. Проверки hooks, доступности и типов не отключаются целиком.
- Stylelint проверяет собственную Windows-тему. Только пять правил обязательного использования токенов и миксинов Alfa Core отключены для CSS интерфейса: приложение не использует `@alfalab/core-components`. Плагин пресета при загрузке может вывести предложение установить эту библиотеку; добавлять ее для прохождения проверки не требуется.

Стандартная команда форматирования пресета охватывает код TS/JS, CSS и JSON. Markdown, YAML и HTML она не переписывает; в HTML приложения намеренно сохраняется точная политика CSP.

Локальное исправление транзитивной зависимости и единственное исключение аудита описаны в [.yarn/patches/README.md](../.yarn/patches/README.md).
