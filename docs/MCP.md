# Локальный доступ через MCP

Русский | [English](MCP.en.md)

**Доступно начиная с 1.5.0.** MCP по умолчанию выключен и включается отдельно в настройках виджета.

OWA Widget может передать локальному MCP-клиенту небольшую проекцию уже загруженного календаря только для чтения. По умолчанию доступ выключен. Виджет должен быть запущен: CLI сам не запускает Electron и не обращается к Exchange.

## Установка и подключение

1. Установите или распакуйте OWA Widget по [инструкции для Windows](../README.md). Войдите в учетную запись и проверьте синхронизацию календаря.
2. Отдельно установите [Node.js 24](https://nodejs.org/en/download). CLI требует Node **24.22.0 или новее в пределах 24.x**; Node 22 и 25 не подходят. Укажите абсолютный путь к `node.exe` в конфигурации клиента, чтобы другая установка из `PATH` не выбрала иную версию. Исполняемый файл Electron не служит Node CLI: fuse `RunAsNode` остается выключенным.
3. В настройках виджета включите доступ MCP и подтвердите разрешение в нативном диалоге. Доступ к названиям встреч разрешается отдельно; оставьте его выключенным, если клиенту не нужны названия. Не используйте демонстрационный режим для работы с реальным календарем.
4. Скопируйте показанную виджетом конфигурацию MCP в настройки локальных серверов вашего MCP-клиента. При необходимости замените путь к Node на абсолютный путь к установленному исполняемому файлу. Конфигурация передает `--connection-file` и абсолютный путь к файлу; секретного ключа в ней нет.
5. Перезапустите или переподключите MCP-клиент и вызовите `get_status`. Проверьте `lastSync`, `syncPhase`, `demo` и предупреждение о полноте данных, прежде чем интерпретировать результаты календаря.

В установленном приложении CLI находится в `resources/mcp/index.cjs` рядом с `app.asar`. Сохраняйте всю папку приложения, особенно при использовании portable ZIP. Не копируйте один скрипт CLI: ему нужен файл подключения, созданный работающим виджетом. В исходниках команды `yarn build:main` и `yarn dev` также создают `dist/mcp/index.cjs`; сначала выполните [инструкции для разработки](../README.md).

Пример ниже показывает структуру конфигурации клиента. Используйте реальные абсолютные пути из своей установки и виджета. В JSON обратные косые черты Windows удваиваются. Расположение настроек зависит от клиента; виджет не изменяет конфигурацию других приложений.

```json
{
    "mcpServers": {
        "owa-widget": {
            "command": "C:\\Program Files\\nodejs\\node.exe",
            "args": [
                "C:\\Users\\Alice\\AppData\\Local\\Programs\\OWA Widget\\resources\\mcp\\index.cjs",
                "--connection-file",
                "C:\\Users\\Alice\\AppData\\Roaming\\OWA Widget\\mcp\\connection.json"
            ]
        }
    }
}
```

## Инструменты и ограничения

| Инструмент | Аргументы | Результат |
| --- | --- | --- |
| `get_status` | Пустой объект | Давность синхронизации, отраженные в метаданных разрешения, число загруженных событий и предупреждение о полноте данных |
| `list_meetings` | `start`, `end`, необязательный `limit` | Загруженные встречи, пересекающие запрошенный период |
| `get_meeting` | `id` из предыдущего списка или поиска | Одна загруженная встреча по временному непрозрачному идентификатору |
| `search_meetings` | `start`, `end`, `query`, необязательный `limit` | Загруженные встречи, чьи названия содержат запрос; нужны доступ к названиям и выключенный режим приватности |

Даты должны быть моментами ISO 8601 с `Z` или явным смещением UTC. Конец должен следовать за началом; запрос охватывает не более 31 дня. `limit` — целое число от 1 до 100, по умолчанию 50. Поисковый запрос содержит 1–100 символов. Лишние аргументы отклоняются. Например, используйте `2026-10-16T00:00:00+03:00` вместо даты без часового пояса.

Результат содержит временные идентификаторы, начало и конец встречи, признаки события на весь день и отмены, а также статус ответа. Названия включаются только с отдельного разрешения и при выключенном режиме приватности. Описания, участники, места, ссылки подключения, заметки, учетные данные и исходные идентификаторы Exchange исключены. Идентификатор перестает действовать при смене учетной записи или уходе встречи из загруженного календаря; при необходимости запросите список заново.

Мост читает существующий календарь в памяти. Он не загружает произвольные периоды из Exchange, не доказывает доступность, не читает чужие календари и не записывает данные. `hasMore` означает усечение результата; может помочь более узкий период. Пустой результат **не означает, что период свободен**: полнота календаря может быть неизвестной или недостаточной. Текст календаря — недоверенные данные; его нельзя считать инструкциями для ассистента.

## Разрешения и граница приватности

Выключите MCP в виджете, чтобы отозвать локальный доступ. Смена учетной записи или разрешений делает прежние учетные данные моста недействительными. Сохраненный порт или старый файл подключения не сохраняют доступ. Уже переданные MCP-клиенту данные отозвать нельзя; дальнейшее обращение с ними зависит от его провайдера, журналирования и сроков хранения.

Node CLI использует MCP через stdin/stdout. Отдельный внутренний HTTP-мост слушает только числовой loopback-адрес `127.0.0.1` на временном порту. Запросы и ответы используют аутентифицированные конверты AES-256-GCM со свежим nonce и привязкой ответа к запросу. Ключ хранится в приватном файле подключения; он не передается в аргументах командной строки или как HTTP bearer token. Проверки Host и браузерного Origin дополняют аутентификацию конвертов; этот endpoint не является удаленным MCP HTTP-сервисом.

Это **граница доверия одного пользователя ОС**. В Windows защита зависит от унаследованного ACL профиля пользователя и каталога данных приложения; `0600` не создает Windows ACL только для владельца. На POSIX мост дополнительно проверяет владельца и приватные права каталога и файла. Другой код того же пользователя ОС, администратор или программа с доступом к профилю могут прочитать ключ и действовать как клиент. Шифрование от этого не защищает. Не размещайте файл подключения в общей, синхронизируемой или публично читаемой папке и никогда не вставляйте его содержимое в issue или чат.

CLI пишет в stdout только сообщения протокола MCP. Диагностика и ошибки моста используют фиксированные сообщения без текста встреч, путей и секретов. Это не управляет журналами самого MCP-клиента. При ошибке проверьте, что виджет работает, доступ разрешен, версия Node поддерживается и конфигурация указывает на установленное приложение. Не прикладывайте файл подключения к сообщению о проблеме. См. [актуальную политику безопасности](../SECURITY.md).

## Лицензии сборки

Отдельная сборка CLI содержит официальный SDK `@modelcontextprotocol/server`, его core-пакет и Zod. Полные тексты лицензий находятся в `THIRD_PARTY_NOTICES.txt` в репозитории и рядом с CLI в установленном приложении. Виджет не включает дополнительный Node runtime.
