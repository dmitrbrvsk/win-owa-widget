# OWA Widget для Windows — тест-кейсы для ручного тестирования

## О приложении

«OWA Widget» — небольшое приложение в области уведомлений Windows (в трее). Оно показывает встречи
из корпоративного Exchange, читая их через веб-интерфейс OWA: таймлайн дня в окне у иконки,
обратный отсчёт на самой иконке, напоминания, подключение к звонку одним нажатием, ответы на
приглашения, создание встреч и поиск свободного времени участников.

Почту приложение не читает — только календарь. Все запросы идут на один сервер Exchange, указанный
в настройках; телеметрии, автообновления и обращений к другим сайтам нет.

## Что нужно тестировщику

| Что | Зачем |
|---|---|
| Компьютер с Windows 10 или Windows 11 (x64) | Целевая система. Отдельно отметьте, если у вас ARM64: на нём приложение не проверялось (x64-установщик работает там в эмуляции, родной — `OWA-Widget-Setup-<версия>-arm64.exe`). |
| Доступ к корпоративному серверу OWA (локальный Exchange) | Основной сценарий. Нужен адрес сервера, как он выглядит в адресной строке браузера, например `mail.company.ru`. |
| Включённая корпоративная сеть (VPN) | Без неё сервер недоступен; это также отдельный набор проверок. |
| Второй почтовый ящик (коллега или тестовая учётная запись) | Чтобы присылать себе приглашения, переносить и отменять встречи, проверять занятость. |
| Доступ к OWA в браузере | Чтобы сверять, что приложение показывает то же, что и сервер. |
| Второй монитор и возможность включить масштабирование 150 % | Проверки размещения окон. |

Приложение рассчитано на локальный (on-premises) Exchange со входом по форме OWA или встроенным
входом Windows. Exchange Online (Microsoft 365) и вход через отдельный портал единого входа
(ADFS, Azure AD) не поддерживаются.

## Где взять сборку и как её поставить

Сборки лежат на странице релизов проекта:
`https://github.com/dmitrbrvsk/win-owa-widget/releases/latest`.

Там два файла:

1. **Установщик** `OWA-Widget-Setup-<версия>.exe`. Ставится в профиль пользователя, права
   администратора не нужны. Создаёт ярлык в меню «Пуск» (без него Windows не доставляет уведомления
   приложения) и удаляется через «Параметры → Приложения».
2. **Переносимая сборка** `OWA-Widget-<версия>-portable-x64.zip`. Распакуйте в любую папку и
   запустите `OWA Widget.exe`. Ярлыка в меню «Пуск» нет, поэтому уведомления Windows из неё не
   гарантируются.

**Перед запуском сверьте контрольную сумму.** Установщик не подписан сертификатом, поэтому
SmartScreen показывает предупреждение. В PowerShell выполните
`Get-FileHash .\OWA-Widget-Setup-<версия>.exe -Algorithm SHA256` и сравните результат со строкой в
файле `SHA256SUMS.txt` на странице релиза. Только после совпадения нажимайте «Подробнее» →
«Выполнить в любом случае».

## Как сообщать об ошибке

В сообщении обязательно укажите:

1. **Версию приложения** — она написана в подвале окна у трея, справа внизу (строка вида `v1.0.0`).
2. **Из какой сборки** вы запускали приложение: установщик или переносимый архив.
3. **Журнал работы.** Настройки → Диагностика → «Открыть папку с журналом». Файл
   `%APPDATA%\OWA Widget\logs\owa-widget.log` (до 1 МБ, при переполнении старая часть сохраняется
   рядом с суффиксом `.1`). В журнале нет паролей, cookie, названий и содержимого встреч, поэтому
   его безопасно прикладывать.
4. **Шаги воспроизведения**, что вы ожидали увидеть и что увидели, со снимком экрана.

Об ошибках — в раздел Issues репозитория. Об уязвимостях — **не в открытые Issues**, а через
Security → Report a vulnerability.

## Как устроен тест-кейс

У каждого кейса одинаковые поля: **ID**, **Название**, **Предусловия**, **Шаги**,
**Ожидаемый результат**, **Приоритет** (высокий / средний / низкий). Номер идёт внутри своей
области, например `НАСТР-03`.

## 1. Установка и первый запуск (УСТ)

### УСТ-01 — Проверка контрольной суммы установщика
- **ID:** УСТ-01
- **Название:** Проверка контрольной суммы установщика
- **Предусловия:** Скачаны `OWA-Widget-Setup-<версия>.exe` и `SHA256SUMS.txt` со страницы релиза.
- **Шаги:**
  1. Откройте PowerShell в папке с загрузками.
  2. Выполните `Get-FileHash .\OWA-Widget-Setup-<версия>.exe -Algorithm SHA256`.
  3. Сравните значение `Hash` со строкой для этого файла в `SHA256SUMS.txt`.
- **Ожидаемый результат:** Значения совпадают посимвольно (регистр букв не важен). Если не
  совпали — файл испорчен или подменён, устанавливать его нельзя.
- **Приоритет:** высокий

### УСТ-02 — Установка из `.exe` без прав администратора
- **ID:** УСТ-02
- **Название:** Установка из `.exe` без прав администратора
- **Предусловия:** Учётная запись Windows без прав администратора, приложение ранее не ставилось.
- **Шаги:**
  1. Запустите установщик.
  2. На экране SmartScreen нажмите «Подробнее» → «Выполнить в любом случае».
  3. Дождитесь завершения установки.
- **Ожидаемый результат:** Запрос прав администратора (UAC) не появляется, установка проходит в
  один шаг без вопросов, в меню «Пуск» появляется ярлык «OWA Widget».
- **Приоритет:** высокий

### УСТ-03 — Первый запуск: сразу открываются настройки с подставленным адресом
- **ID:** УСТ-03
- **Название:** Первый запуск: сразу открываются настройки с подставленным адресом
- **Предусловия:** Установка выполнена, приложение никогда не запускалось на этом профиле.
- **Шаги:**
  1. Запустите «OWA Widget» из меню «Пуск».
  2. Посмотрите на появившееся окно.
- **Ожидаемый результат:** Открывается окно «OWA Widget — настройки», в поле адреса сервера заранее
  вписан `owa.alfabank.ru`, курсор стоит в этом поле. Под полем подсказка, что нужен адрес OWA из
  адресной строки браузера.
- **Приоритет:** высокий

### УСТ-04 — Запуск переносимой сборки из архива
- **ID:** УСТ-04
- **Название:** Запуск переносимой сборки из архива
- **Предусловия:** Скачан `OWA-Widget-<версия>-portable-x64.zip`, установленная копия не запущена.
- **Шаги:**
  1. Распакуйте архив в отдельную папку (например, на рабочий стол).
  2. Запустите `OWA Widget.exe` из этой папки.
- **Ожидаемый результат:** Приложение запускается без установки, иконка появляется в области
  уведомлений, открываются настройки (первый запуск для этого профиля) или окно у трея.
- **Приоритет:** средний

### УСТ-05 — Две копии запущены одновременно (одна и та же версия)
- **ID:** УСТ-05
- **Название:** Две копии запущены одновременно (одна и та же версия)
- **Предусловия:** Приложение уже запущено (иконка в трее есть).
- **Шаги:**
  1. Запустите тот же `OWA Widget.exe` (или ярлык) второй раз.
  2. Посмотрите на экран и на область уведомлений.
- **Ожидаемый результат:** Вторая копия не появляется: в трее остаётся одна иконка, а уже
  работающая копия просто показывает своё окно у трея.
- **Приоритет:** средний

### УСТ-06 — Запуск другой версии поверх работающей
- **ID:** УСТ-06
- **Название:** Запуск другой версии поверх работающей
- **Предусловия:** Запущена одна версия (например, из архива), скачана сборка другой версии.
- **Шаги:**
  1. Не завершая первую копию, запустите сборку другой версии.
  2. Подождите до 10 секунд.
- **Ожидаемый результат:** Старая копия завершается сама, запускается новая, в трее остаётся одна
  иконка. Если старая копия не ответила, появляется окно «OWA Widget уже запущен» с объяснением,
  как её закрыть вручную.
- **Приоритет:** средний

### УСТ-07 — Иконка в трее в Windows 11 под стрелкой «^»
- **ID:** УСТ-07
- **Название:** Иконка в трее в Windows 11 под стрелкой «^»
- **Предусловия:** Windows 11, приложение только что установлено и запущено.
- **Шаги:**
  1. Посмотрите на панель задач: видна ли иконка приложения.
  2. Если нет — нажмите стрелку «^» (показать скрытые значки).
  3. Перетащите иконку на видимую часть панели.
- **Ожидаемый результат:** Иконка находится либо на панели, либо под стрелкой «^»; после
  перетаскивания она остаётся на панели и после перезапуска приложения.
- **Приоритет:** средний

### УСТ-08 — Знакомство при первом запуске: четыре шага
- **ID:** УСТ-08
- **Название:** Знакомство при первом запуске: четыре шага
- **Предусловия:** Приложение ещё ни разу не запускалось на этом пользователе (папка
  `%APPDATA%\OWA Widget` удалена).
- **Шаги:**
  1. Запустите приложение.
  2. Пройдите все четыре шага кнопкой «Далее», на каждом прочитайте текст.
  3. Вернитесь на шаг назад кнопкой «Назад», затем снова вперёд.
  4. Попробуйте стрелки «влево» и «вправо» на клавиатуре.
  5. На последнем шаге нажмите «Перейти к настройкам».
- **Ожидаемый результат:** Сразу после запуска открывается окно знакомства на первом шаге; шаги
  переключаются кнопками, точками внизу и стрелками; на последнем шаге кнопка называется «Перейти
  к настройкам» и открывает настройки, окно знакомства закрывается.
- **Приоритет:** высокий

### УСТ-09 — Знакомство можно пропустить, и второй раз оно не появляется
- **ID:** УСТ-09
- **Название:** Знакомство можно пропустить, и второй раз оно не появляется
- **Предусловия:** Первый запуск на чистом профиле.
- **Шаги:**
  1. На первом же шаге нажмите «Пропустить» (в другой раз — крестик в углу или Esc).
  2. Завершите настройку сервера, выйдите из приложения и запустите его снова.
  3. Запустите приложение ещё раз после перезагрузки компьютера.
- **Ожидаемый результат:** Знакомство закрывается сразу, после него открываются настройки (сервер
  ещё не настроен). При всех следующих запусках окно знакомства больше не появляется.
- **Приоритет:** высокий

### УСТ-10 — Знакомство открывается из настроек и не мешает работе
- **ID:** УСТ-10
- **Название:** Знакомство открывается из настроек и не мешает работе
- **Предусловия:** Приложение настроено, календарь загружен.
- **Шаги:**
  1. Откройте Настройки → раздел «Диагностика» → «Показать знакомство с приложением».
  2. Пролистайте до последнего шага.
  3. Закройте окно.
- **Ожидаемый результат:** Окно знакомства открывается, на последнем шаге кнопка называется
  «Готово» (а не «Перейти к настройкам»), после закрытия настройки и окно у трея работают как
  прежде, календарь не перезагружается.
- **Приоритет:** средний

### УСТ-11 — После обновления знакомство не показывается
- **ID:** УСТ-11
- **Название:** После обновления знакомство не показывается
- **Предусловия:** Установлена и настроена предыдущая версия, профиль пользователя сохранён.
- **Шаги:**
  1. Поставьте новую версию поверх старой.
  2. Запустите приложение.
- **Ожидаемый результат:** Окно знакомства не открывается, приложение сразу работает с прежними
  настройками.
- **Приоритет:** средний

## 2. Настройки и подключение (НАСТР)

### НАСТР-01 — Адрес почты в поле сервера отклоняется
- **ID:** НАСТР-01
- **Название:** Адрес почты в поле сервера отклоняется
- **Предусловия:** Открыты настройки.
- **Шаги:**
  1. Сотрите адрес и введите `ivanov@company.ru`.
  2. Посмотрите на подпись под полем.
- **Ожидаемый результат:** Поле подсвечивается как ошибочное, под ним красное сообщение о том, что
  это адрес почты, а не сервера, и что нужен адрес OWA из адресной строки браузера. Кнопка
  сохранения адреса недоступна.
- **Приоритет:** высокий

### НАСТР-02 — Вход под учётной записью Windows (логин и пароль пусты)
- **ID:** НАСТР-02
- **Название:** Вход под учётной записью Windows (логин и пароль пусты)
- **Предусловия:** VPN включён, указан рабочий адрес OWA, поля логина и пароля пусты.
- **Шаги:**
  1. Нажмите «Проверить подключение».
  2. Дождитесь ответа.
- **Ожидаемый результат:** Зелёное сообщение «Подключено. Встреч на неделю: N», где N совпадает с
  числом встреч в OWA в браузере за ближайшую неделю. Пароль при этом нигде не запрашивается.
- **Приоритет:** высокий

### НАСТР-03 — Вход по логину и паролю
- **ID:** НАСТР-03
- **Название:** Вход по логину и паролю
- **Предусловия:** VPN включён, указан рабочий адрес OWA, известны логин (в виде `ДОМЕН\логин`) и
  пароль.
- **Шаги:**
  1. Введите логин и пароль.
  2. Нажмите «Проверить подключение», затем «Сохранить».
  3. Закройте и снова откройте настройки.
- **Ожидаемый результат:** Проверка проходит успешно; после повторного открытия настроек в поле
  пароля видна подпись о том, что пароль сохранён, а само поле пустое (точки-заполнители).
- **Приоритет:** высокий

### НАСТР-04 — Неверный пароль: одна попытка, синхронизация останавливается
- **ID:** НАСТР-04
- **Название:** Неверный пароль: одна попытка, синхронизация останавливается
- **Предусловия:** Рабочий адрес сервера, настоящий логин, заведомо **неверный** пароль. Учётная
  запись не находится на грани блокировки.
- **Шаги:**
  1. Введите неверный пароль и сохраните настройки.
  2. Откройте окно у трея и несколько раз нажмите кнопку обновления.
  3. Подождите 10–15 минут, периодически нажимая обновление.
  4. Посмотрите журнал (Диагностика → «Открыть папку с журналом»).
  5. Введите правильный пароль и сохраните настройки.
- **Ожидаемый результат:** В подвале окна ошибка входа с кнопкой, открывающей настройки, а в журнале
  **одна** неудачная попытка — повторных попыток нет ни от автоматической синхронизации, ни от
  нажатий «Обновить», поэтому доменная учётная запись не блокируется. После правильного пароля
  приложение само входит заново и загружает встречи.
- **Приоритет:** высокий

### НАСТР-05 — Самоподписанный (внутренний) сертификат: системное окно с отпечатком
- **ID:** НАСТР-05
- **Название:** Самоподписанный (внутренний) сертификат: системное окно с отпечатком
- **Предусловия:** Сервер OWA с сертификатом, которому Windows не доверяет. Отпечаток сертификата
  заранее получен у ИТ-отдела или из браузера.
- **Шаги:**
  1. Укажите адрес такого сервера и нажмите «Проверить подключение».
  2. Прочитайте сообщение об ошибке и данные сертификата под ним.
  3. Нажмите «Доверять сертификату».
  4. В появившемся окне Windows сверьте отпечаток и нажмите «Довериться этому сертификату».
- **Ожидаемый результат:** Сообщение называет причину (например, «выдан центром сертификации,

## 6. Приглашения и ответы на них (ПРИГЛ)

### ПРИГЛ-01 — Новые приглашения собраны вверху окна
- **ID:** ПРИГЛ-01
- **Название:** Новые приглашения собраны вверху окна

- **Шаги:**

  2. Нажмите на заголовок «Новые приглашения».

- **ID:** ПРИГЛ-02
- **Название:** Ответ «Принять»

  1. Нажмите «Принять».
  2. Проверьте второй ящик (ящик организатора).
- **Ожидаемый результат:** В окне появляется сообщение об отправленном ответе, кнопка «Принять»

### ПРИГЛ-03 — Ответы «Под вопросом» и «Отклонить»
- **ID:** ПРИГЛ-03
- **Название:** Ответы «Под вопросом» и «Отклонить»
- **Предусловия:** Есть два новых приглашения.
- **Шаги:**
  1. На первом нажмите «Под вопросом», на втором — «Отклонить».
  2. Проверьте оба в OWA и в ящике организатора.
- **Ожидаемый результат:** Организатор получает соответствующие ответы; в приложении отклонённая
  встреча перестаёт учитываться в отсчёте на иконке и в напоминаниях.
- **Приоритет:** высокий

### ПРИГЛ-04 — Приглашение уходит из блока после ответа
- **ID:** ПРИГЛ-04
- **Название:** Приглашение уходит из блока после ответа
- **Предусловия:** Выполнен ПРИГЛ-02.
- **Шаги:**
  1. Дождитесь следующей синхронизации (до 5 минут) или нажмите обновление.
  2. Посмотрите на блок «Новые приглашения» и на иконку в трее.
- **Ожидаемый результат:** Счётчик уменьшается, отвеченное приглашение из блока пропадает; когда
  непринятых не остаётся, жёлтая точка на иконке исчезает.
- **Приоритет:** средний

### ПРИГЛ-05 — Приглашение со ссылкой на незнакомый сайт
- **ID:** ПРИГЛ-05
- **Название:** Приглашение со ссылкой на незнакомый сайт
- **Предусловия:** Со второго ящика прислано приглашение, в описании которого ссылка на сайт, не
  относящийся к Teams, Zoom, Webex, Google Meet или KTalk (например, `https://example.org/room/1`).
- **Шаги:**
  1. Откройте карточку встречи и посмотрите на кнопку подключения и на ссылку в описании.
  2. Нажмите правой кнопкой на эту встречу в таймлайне и посмотрите меню иконки в трее.
- **Ожидаемый результат:** Рядом с «Подключиться» (в карточке, в карточке ближайшей встречи и в
  меню иконки в трее) написан настоящий узел ссылки, например `example.org`; при наведении
  подсказка показывает тот же узел. Нигде нет кнопки, открывающей ссылку без показа её адреса.
- **Приоритет:** высокий

### ПРИГЛ-06 — Название встречи, притворяющееся кнопкой
- **ID:** ПРИГЛ-06
- **Название:** Название встречи, притворяющееся кнопкой
- **Предусловия:** Со второго ящика прислано приглашение с названием вида
  `Подключиться  ✓ Принять  — нажмите здесь`.
- **Шаги:**
  1. Откройте окно у трея и карточку этой встречи.
  2. Попробуйте нажать на «кнопку» внутри названия.
- **Ожидаемый результат:** Название остаётся обычным текстом: нажатие на него открывает карточку
  встречи и ничего не отправляет на сервер. Настоящие кнопки ответа визуально отличаются от текста
  названия.
- **Приоритет:** высокий

### ПРИГЛ-07 — Предупреждение о пересечении встреч
- **ID:** ПРИГЛ-07
- **Название:** Предупреждение о пересечении встреч
- **Предусловия:** В календаре есть принятая встреча 11:00–12:00; со второго ящика прислано приглашение на 11:30–12:30.
- **Шаги:**
  1. Откройте окно у трея: в блоке «Новые приглашения» найдите это приглашение.
  2. Откройте его карточку.
  3. Нажмите «Отклонить» рядом с пересекающейся встречей, затем подтвердите второй раз.
- **Ожидаемый результат:** У приглашения в списке стоит отметка о пересечении, в карточке над ответами жёлтый блок «Пересекается с вашей встречей» с названием и временем той встречи. Кнопка «Отклонить» требует второго нажатия и только после него отправляет отказ на ту встречу (если она ваша, кнопки нет). Принятые встречи без пересечения блока не показывают.
- **Приоритет:** средний

### ПРИГЛ-08 — Ответ с комментарием
- **ID:** ПРИГЛ-08
- **Название:** Ответ с комментарием
- **Предусловия:** Открыта карточка приглашения, на которое вы не ответили.
- **Шаги:**
  1. Нажмите «Ответить с комментарием», выберите «Под вопросом», введите текст.
  2. Нажмите «Отправить» и в системном окне Windows выберите «Отмена».
  3. Повторите и выберите «Отправить».
  4. Проверьте ящик организатора.
- **Ожидаемый результат:** В системном окне показаны встреча, ваш ответ и текст комментария; по умолчанию и по Esc выбрано «Отмена», при отмене ничего не уходит. После «Отправить» организатор получает ответ с вашим текстом, в окне виджета появляется подтверждение. Пустой комментарий отправить нельзя, счётчик не даёт ввести больше 1000 символов.
- **Приоритет:** высокий

### ПРИГЛ-09 — Предложить другое время
- **ID:** ПРИГЛ-09
- **Название:** Предложить другое время
- **Предусловия:** Открыта карточка чужого приглашения.
- **Шаги:**
  1. Нажмите «Предложить другое время», выберите новые дату и время.
  2. Выберите время в прошлом, затем время с концом раньше начала, затем корректное.
  3. Добавьте комментарий и отправьте, подтвердив в системном окне.
- **Ожидаемый результат:** Для времени в прошлом и для обратного интервала показано понятное сообщение, отправить нельзя; если на предложенное время у вас есть встречи, они показаны. Организатор получает письмо с вашим ответом (под вопросом или отказ) и текстом с новым временем. Встреча в его календаре сама не переносится, это письмо, а не встречное предложение Outlook.
- **Приоритет:** высокий

### ПРИГЛ-10 — Личная заметка к встрече
- **ID:** ПРИГЛ-10
- **Название:** Личная заметка к встрече
- **Предусловия:** Открыта карточка любой встречи.
- **Шаги:**
  1. В поле «Моя заметка» введите текст, подождите секунду: появится «Сохранено».
  2. Закройте окно, откройте снова эту встречу.
  3. Посмотрите на таймлайн.
  4. Проверьте ящик организатора и сетевой трафик.
- **Ожидаемый результат:** Заметка сохранилась и возвращается; у встречи на таймлайне виден значок карандаша. Заметка никуда не отправляется: ни на сервер Exchange, ни в какой-либо другой адрес, организатор и участники её не видят. Заметка хранится в зашифрованном файле профиля; если шифрование Windows недоступно, сообщается, что заметка не сохранена.
- **Приоритет:** средний

### ПРИГЛ-11 — Удаление всех заметок
- **ID:** ПРИГЛ-11
- **Название:** Удаление всех заметок
- **Предусловия:** Есть хотя бы одна заметка (ПРИГЛ-10).
- **Шаги:**
  1. Настройки → «Заметки к встречам» → «Удалить все заметки».
  2. В системном окне выберите «Отмена», затем повторите и выберите «Удалить».
- **Ожидаемый результат:** При отмене заметки остаются. После подтверждения все заметки и значки на таймлайне исчезают, показано сообщение об удалении. Старые заметки (встречи старше примерно трёх месяцев) стираются сами.
- **Приоритет:** средний

### ПОИСК-04 — Запрос не уходит на сервер и не пишется в журнал

- **ID:** НАПОМ-06
- **Название:** Режим «Не беспокоить» Windows

## Что не проверено разработчиком

Это места, где вероятность найти ошибку выше всего: по документации README и SECURITY они написаны
«по бумаге» и проверены только автоматическими тестами и поддельным сервером, но ни разу не
работали на настоящей системе. Начинайте проверку с них.

1. **Уведомления Windows с кнопками и выпадающим списком.** Сами напоминания и уведомления об
   изменениях написаны по документации и проверены тестами логики (какая кнопка что делает), но
   глазами на живой Windows их никто не видел. Проверяйте: вид уведомления, работу кнопок
   «Подключиться», «Отложить», «Принять», работу выпадающего списка откладывания, поведение при
   «Не беспокоить». Если что-то не так, переключитесь на «Окно приложения» и опишите, что именно.
   → Кейсы НАПОМ-01…НАПОМ-08, ИЗМ-01…ИЗМ-06.
2. **Системное окно подтверждения отправки приглашений.** Его текст проверен тестами, но нажатия
   на настоящем Windows — нет. → СОЗД-05, СОЗД-06, СОЗД-07, СОЗД-08, БЕЗОП-01, БЕЗОП-02.
3. **Создание встреч, подсказки людей из адресной книги и поиск свободного времени против
   настоящего Exchange.** Запросы написаны по документации EWS и проверялись только на поддельном
   сервере. **Первую встречу создайте без участников или только с собой.** → весь раздел СОЗД,
   весь раздел СВОБ.
4. **Мигание иконки и жёлтая точка непринятых приглашений на настоящей панели задач Windows.**
   Картинки рисуются и проверяются тестами, но на живом трее не смотрелись. → ТРЕЙ-01, ТРЕЙ-03,
   ТРЕЙ-05, ТРЕЙ-07.
5. **Встроенный вход Windows (Kerberos / NTLM) против настоящего Exchange.** → НАСТР-02.
6. **Работа на ARM64.** Сборка под ARM64 выпускается отдельным установщиком `…-arm64.exe`, но не проверялась вообще. Если у вас такой
   компьютер, пройдите по разделам полностью и отмечайте всё, что отличается.
7. **Ответ на приглашение с текстом («Ответить с комментарием», «Предложить другое время») против настоящего Exchange.** Текст уходит в `NewBodyContent` запроса ответа; как именно настоящий Exchange вставит его в письмо организатору, проверено только на поддельном сервере. → ПРИГЛ-08, ПРИГЛ-09.
8. **Не поддерживается и не проверялось в принципе:** Exchange Online (Microsoft 365) и вход через
   отдельный портал единого входа (ADFS, Azure AD). Ожидаемое поведение — приложение
   останавливается и объясняет, куда его перенаправили (НАСТР-10), а не пытается войти.
