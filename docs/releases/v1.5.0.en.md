**Local MCP, safe account-data migration and a more responsive calendar.** This release includes all completed changes since 1.4.4, including fixes from the security and performance audits.

**Download:** [Windows x64](https://github.com/dmitrbrvsk/win-owa-widget/releases/download/v1.5.0/OWA-Widget-Setup-1.5.0.exe) · [Windows ARM64](https://github.com/dmitrbrvsk/win-owa-widget/releases/download/v1.5.0/OWA-Widget-Setup-1.5.0-arm64.exe) · [Portable x64](https://github.com/dmitrbrvsk/win-owa-widget/releases/download/v1.5.0/OWA-Widget-1.5.0-portable-x64.zip)

## Changes

### New features

- **Local read-only MCP.** Connect a local MCP client to check synchronization status, list loaded meetings and their times, or search meeting titles. Access is off by default and requires native consent. Titles need a separate permission; privacy mode hides them and disables title search. Account changes revoke access. [MCP setup and limitations](https://github.com/dmitrbrvsk/win-owa-widget/blob/v1.5.0/docs/MCP.en.md).
- **Recovery for older groups and notes.** Ordinary manual accounts migrate automatically. When the old format cannot reliably identify the owner, Settings offers “Recover for the current account” with native confirmation.
- **English documentation.** The guide, FAQ, security model, changelog, bug-report forms and contributor instructions are available in both languages. Added the MIT license file, compatibility information before installation and prominent build links.

### Security and data preservation

- **Fixed an account-owner collision.** Windows SSO and a manual `windows` login on the same server no longer share ownership of groups and notes. Ambiguous legacy records can be assigned to only one account.
- **Migration preserves originals.** Original files stay encrypted. Only the selected owner can resume after an interrupted write; edits remain blocked until completion. Current notes win conflicts, and duplicate group names receive a numeric suffix. Unreadable files are not overwritten.
- **Bound native confirmations to their context.** Changing the server, certificate fingerprint or account during a native dialog invalidates obsolete approval. Deletion consent cannot delete notes belonging to an account selected later.
- **No unexpected sign-in fallback.** If a saved password becomes temporarily unavailable, manual authentication stops instead of falling back to Windows SSO under a different cache owner.
- **Bound input processing.** Excessively complex server responses are rejected before expensive parsing. Invalid MCP requests cannot consume the authenticated operation quota; slow connections have an absolute deadline. Vulnerable development-tool dependencies were updated or locally patched, with regression tests.

### Performance and reliability

- **Less repeated work during synchronization.** Status updates no longer copy the entire calendar into every open window; date formatters are reused.
- **More manageable busy days.** Very dense schedules and all-day meetings use 50-record pages with totals. Every meeting remains accessible, and overlap layout is faster.
- **Stable scrolling.** Clock and calendar updates preserve manual availability scrolling, while local date and timezone changes are handled separately.
- **Screens load when opened.** Production JS is minified, unused MCP locales are excluded while preserving validation, and browser demos build separately. This reduces interface code loading, rather than the Electron runtime itself.
- **More reliable notification links.** Meeting details wait for the interface to become ready, including on a cold window.

### Important when updating

- **The calendar resynchronizes.** Legacy cache is not assigned to the new account key. MCP permission stored under an older key is not restored either: grant consent again if needed.
- **Check the account before recovery.** Verify the server and sign-in mode. Cancelling imports nothing. The older ownerless `notes.bin` stays separate and is not imported. Do not delete originals or migration records, or attach them to bug reports. [Data migration](https://github.com/dmitrbrvsk/win-owa-widget/blob/v1.5.0/docs/GUIDE.en.md#migrating-older-account-data).
- **MCP is optional.** Its adapter requires a separate Node.js 24.22+ runtime within 24.x; ordinary widget use needs no separate Node.js installation. MCP sees only loaded meetings, so an empty result does not prove free time. Calendar writes, attendees, descriptions, links, notes and credentials are excluded. A connected AI client may forward permitted data to its provider: follow your company policy.

## Installation

- **OWA-Widget-Setup-1.5.0.exe** — installer for Windows 10/11 x64; runs on ARM64 under emulation. Administrator rights are not required.
- **OWA-Widget-Setup-1.5.0-arm64.exe** — Windows ARM64 installer.
- **OWA-Widget-1.5.0-portable-x64.zip** — extract and run `OWA Widget.exe` without installation.

## Verify the files

The installer is not yet Authenticode-signed, so Windows SmartScreen may display a warning. Before running it, compare its checksum with `SHA256SUMS.txt` from this release. Use GitHub CLI to verify build provenance:

```powershell
Get-FileHash .\OWA-Widget-Setup-1.5.0.exe -Algorithm SHA256
gh attestation verify .\OWA-Widget-Setup-1.5.0.exe --repo dmitrbrvsk/win-owa-widget
```
